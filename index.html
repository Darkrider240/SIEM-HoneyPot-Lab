Interactive Lab Guidebook

One VM, Full Security Lab Concept

Traditional cybersecurity home labs assume infinite resource overhead. Recommending four parallel virtual servers (e.g., Attacker, Firewall, Honeypot, SIEM Node) on a low-spec CPU with 12 GB Host RAM guarantees severe host memory thrashing and heat throttling.

The Architecture: Instead of scaling horizontally via hypervisor overhead, this lab scales vertically. A single 4 GB RAM Kali Linux VM is provisioned to play all roles.

  • Network Loopback (127.0.0.1) bridges the attack console and security sensor array. Since attacks target localhost, no physical hypervisor SPAN network configuration is required.
  • Docker Container Daemonization isolates network listening environments. Cowrie handles fake interactive terminal layers within 180 MB memory limits.
  • JVM Heap Compaction restricts Wazuh's default 2-4 GB memory footprints. Standard OpenSearch limits are scaled down to 512 MB, enabling a professional SIEM stack to run alongside IDS systems.

Deploying Mapped Configs into Kali

To push the low-resource scripts and rule templates generated here into the guest VM, choose one of these two transfer avenues:

Avenue 1: Automated SCP Transfer (Recommended)

1. Inside Kali VM, ensure the SSH server is running:

2. Open PowerShell on your Windows host inside this project directory and run the deployment automation:

Avenue 2: Shared Folder Mount Configuration

1. In VirtualBox, go to **Kali VM Settings → Shared Folders → Add Shared Folder**.

2. Configure the directory fields:

  • Folder Path: `C:\Users\HP\.gemini\antigravity\scratch\siem-honeypot-companion\lab-configs`
  • Folder Name: `lab_configs`
  • Mount Point: `/media/sf_lab_configs`
  • Check Options: Auto-mount (ON) & Make Permanent (ON).

3. Mount the directories inside your Kali Terminal session:

# Add user to VirtualBox group for folder read-write access:
sudo usermod -aG vboxsf $USER
# Mount file layers:
mkdir -p ~/lab/configs
cp -r /media/sf_lab_configs/* ~/lab/configs/
chmod +x ~/lab/configs/*.sh

Low-Spec Lab Defense Checklist

Symptom: Kali Desktop freezes or stops responding.

  • Cause: Memory exhaustion triggering OS pagination lockups.
  • Triage: Open a terminal session on your Windows Host and run SSH into the VM: `ssh kali@`. Immediately execute `docker stop $(docker ps -a -q)` and `sudo pkill suricata` to release host memory. Wait 30 seconds for the garbage collector to clear memory lines.

Symptom: Wazuh Indexer fails to boot with status 'exit 137'.

  • Cause: Linux OOM killer terminated the JVM container due to RAM resource starvation.
  • Triage: Verify that the 2 GB Swapfile was mounted successfully (`swapon --show`). If inactive, execute the swap configuration script: `sudo ~/lab/configs/setup-swap.sh`.

Symptom: Suricata alerts fail to trigger during port scans.

  • Cause: Inbound interface matching rules failed to resolve eth0 interface.
  • Triage: Find the active network interface on your VM: `ip addr show`. Verify that the interface name matches the interface mapped in `/etc/suricata/suricata.yaml` inside the `af-packet` block.
